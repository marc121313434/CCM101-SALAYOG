Looking back on this mission, the cloud infrastructure component that stood out to me the most was the compute resource. It feels like the heart of any cloud system because it’s where all the processing happens—applications run, data gets handled, and workloads are managed. Without compute power, the other components like storage or networking wouldn’t really have a purpose.

I also realized how much Linux supports cloud computing. Most cloud servers rely on Linux because it’s lightweight, secure, and flexible. Using simple commands, I was able to check the operating system, CPU, memory, and disk space. That experience showed me how Linux acts as the backbone for virtual machines in AWS, Azure, and GCP.

Another big takeaway is the importance of technical documentation before deploying infrastructure. Writing things down—like configurations, commands, and design choices—makes it easier to stay consistent, troubleshoot problems, and share knowledge with others. Documentation isn’t just paperwork; it’s a guide that helps teams avoid mistakes and build reliable systems.

Through this lab, I picked up new skills in system investigation, Markdown writing, and cloud architecture design. I also learned how to connect what I see in a Linux environment to equivalent cloud services, which made the concepts feel more practical and real.
